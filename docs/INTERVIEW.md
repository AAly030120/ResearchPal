# ResearchPal · 面试与简历指南（INTERVIEW.md）

> 把项目写进简历、讲给面试官听时，重点不是「我写了哪些代码」，而是「我怎么定义一个 AI 产品、怎么做取舍、怎么验证」。
> 本文档提供可直接套用的简历条目，以及高频面试题的回答框架。

---

## 一、简历要点（可直接改写使用）

> 写法原则：**动词开头 + 做了什么 + 带来的结果/权衡 + 体现的产品/技术判断**。方括号处替换为你自己的真实数据。

- **产品定义与落地**：独立定义并交付 ResearchPal——一款面向高校学生的 AI 科研助手，覆盖文献总结、数据分析出图、一键 PPT、代码生成、文件翻译五大场景，把分散的科研流程做成一站式工作台。
- **多模型架构**：设计统一的多模型路由层（OpenAI / DeepSeek / 智谱 GLM / 通义千问），以 OpenAI-compatible 适配实现零成本切换，并用「默认 mini + 重任务可升级 + 自动回退」把单任务成本压到最低。
- **安全与工程**：为 AI 生成的代码设计隔离沙箱（禁用危险模块、超时限制、图表捕获），在不牺牲安全的前提下把「上传数据→出图」闭环做到端到端可用。
- **可演示性**：实现 Demo 模式——无 API Key 也能跑通全部功能（数据分析在沙箱真实执行并出图），把评审/协作门槛降到「clone 即体验」。
- **产品思维外化**：产出 PRODUCT.md，用 RICE 排功能优先级、定义北极星与分层指标、记录模型选型与学术诚信的权衡，把「为什么做」讲清楚。

## 二、高频面试题回答库

### Q1：你为什么做这个项目？
**回答框架**：痛点 → 机会 → 个人动机。
> 我做科研时发现大量时间花在低价值但高门槛的重复劳动上（读长文献、写分析脚本、排版 PPT）。LLM 已经能自动化这些环节，但工具太割裂、门槛高、不保排版。我想做一个一站式的、低门槛且保质量的助手。对个人而言，这也是验证「用 AI 工具做 AI 产品」这一套方法论的最佳载体。

### Q2：你做的最大的权衡（trade-off）是什么？
**回答框架**：给一个真实取舍 + 理由 + 后果。
> PPT 渲染：我放弃「纯 ppt-master 保真」，改为「内置 python-pptx 渲染器 + 可选 ppt-master 增强」。理由是让仓库零依赖可跑、克隆即出图、不塞 80MB 技能目录；代价是默认版式保真度略低。这是个典型的产品取舍——可用性/可维护性优先于极致效果，且保留了增强路径。

### Q3：你怎么衡量这个产品成不成功？
**回答框架**：北极星 + 分层 + 如何校准。
> 北极星是「周活跃用户完成的的有效 AI 任务数」。再拆激活（7 日完成 ≥2 类任务）、参与（人均周任务数）、留存（4 周）、质量（非 Demo 任务成功率 ≥95%）、成本（单任务 Token 成本）。上线后我会用任务级埋点校准这些假设值，而不是拍脑袋。

### Q4：印象最深的一个技术难点 / bug？
**回答框架**：问题 → 根因 → 解法 → 复盘。
> 发布前发现 PPT 功能依赖一个 80MB 的本地技能目录，而它被 `.gitignore` 排除——别人 clone 后 PPT 直接跑不起来。根因是「硬依赖外部技能」。我加了 python-pptx 内置渲染器做优雅降级，并把该目录加入忽略，彻底去掉硬依赖。复盘：作品项目也要当生产项目对待——「能在自己机器跑」≠「别人能跑」。

### Q5：你是怎么思考 AI 安全的？
**回答框架**：分层——模型安全 + 内容安全 + 学术诚信。
> 三层：①执行安全——AI 生成的代码必须在隔离沙箱跑，禁用危险模块、限超时；②内容安全——翻译/总结定位为「辅助理解」而非代写，UI 明确提示；③学术诚信——不伪造数据或引用，引用严格依据原文元数据。AI 产品的信任是底线。

### Q6：如果给你双倍资源 / 减半资源，你会分别怎么做？
**回答框架**：展示优先级感。
> 减半：砍 RAG 与模板市场，保住五大任务 + 多模型路由 + 安全沙箱这条主线。双倍：优先做 RAG 多轮问答（提升「助手」属性）与成本/质量可观测看板（用数据驱动模型路由），再做模板生态提升留存。

### Q7：你是怎么用 AI 工具来做这个 AI 产品的？（vibe-coding 元叙事）
**回答框架**：方法论 + 反思。
> 我用 AI 编码工具把「spec → build → eval」的循环提速：先用产品文档定义范围，再让工具快速产出前后端骨架，我自己把控架构、安全与产品取舍。关键是我始终扮演「产品负责人」而非「纯执行」——AI 负责实现速度，我负责定义与判断。这也是我觉得 AI 产品岗最需要的协作方式。

### Q8：多模型路由带来什么产品价值？
**回答框架**：成本 + 韧性 + 体验。
> 对用户：可用更便宜的模型做轻任务、在关键时刻切强模型，成本可控；对系统：不绑死单一供应商，某个 Key 失效自动回退，可用性更高；对产品：把「模型」从黑盒变成可配置能力，是 AI 产品差异化的基础。

## 三、面试小贴士

- 被问「最大的坑」时，优先讲**真实发生且你已修复**的（如 Q4 的 ppt-master 依赖），比编故事可信。
- 所有「指标」都标注是「设计假设」还是「真实数据」，诚实最稳。
- 把话题往「产品判断」引：为什么做、怎么排优先级、怎么度量，比罗列功能更得分。
- Demo 模式的价值要主动说：它体现的是「降低他人体验门槛」的产品意识。
